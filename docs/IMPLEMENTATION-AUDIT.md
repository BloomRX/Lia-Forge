## Método e significado dos estados

Foram cruzados documentos, configuração, código-fonte, testes disponíveis e metadados/fontes públicas dos nove repositórios solicitados. Para os projetos externos, foram lidos endpoints/arquivos públicos do GitHub sem clone; a pesquisa é datada e não constitui auditoria de segurança completa, execução, parecer jurídico ou aceitação de licença.

- **`IMPLEMENTED`** — código executável para a capacidade nomeada existe no checkout; não significa que rodou no ambiente-alvo.
- **`VERIFIED`** — somente o comportamento estreito indicado tem evidência de teste/aceitação registrada para inputs e ambiente identificados. Não significa qualidade artística, estabilidade geral ou compatibilidade de outra plataforma.
- **`PARTIALLY_IMPLEMENTED`** — existe um subconjunto real, com etapas/contratos/gates importantes ausentes.
- **`DOCUMENTED`** — a informação/rota está em documentos, sem executor correspondente comprovado.
- **`PLANNED`** — parte da visão/roadmap aceita, sem implementação neste checkout.
- **`EXPERIMENTAL`** — protótipo ou ensaio delimitado, não um caminho de produção estável.
- **`BLOCKED`** — a execução/verificação nomeada não pode avançar até uma dependência, decisão, ambiente ou autorização explícita ser resolvida.
- **`PROPOSED`** — recomendação arquitetural sujeita a decisão; não é compromisso nem código.

O estado se refere à capacidade delimitada de cada linha. A coluna de teste separa teste sintético/de código de execução real. Nenhuma linha baseada em documentação é promovida a `IMPLEMENTED`.

### Achado: 112 links quebrados em `THIRD_PARTY_NOTICES.md` (gerador não alterado)

**Verificação de 2026-11-11 UTC:** o problema **persiste**. `THIRD_PARTY_NOTICES.md` (146.468 bytes) contém 466 links Markdown, dos quais **113 são relativos e 112 não resolvem** para um caminho existente (exemplos: `sindresorhus/is`, `jshttp/accepts`, `ajv-validator/ajv`, `chalk/ansi-regex`, `chalk/ansi-styles`). São todos shorthand `owner/repo` de repositórios GitHub emitidos como se fossem caminho relativo.

**Causa raiz (localizada, não corrigida aqui):** `scripts/generate_third_party_notices.py`, função `repository_url()` na **linha 36**. Ela normaliza `git+ssh://git@github.com/…`, `git+…`, `git://…`, `github:…` e remove sufixo `.git`, mas **não trata o shorthand npm simples** `"owner/repo"` (sem esquema), que o npm aceita no campo `repository`. O valor cru é retornado e emitido na linha 87 como alvo de um link Markdown (no formato "texto entre colchetes seguido do alvo entre parênteses"), produzindo um **link relativo inexistente**. Quando o manifesto não declara `repository`, o fallback já é absoluto (`https://www.npmjs.com/package/…`) — por isso apenas 112 de 466 links falham.

**Correção mínima recomendada (para tarefa futura autorizada):** acrescentar, **imediatamente antes do `return url`** de `repository_url()`, um guarda que detecte valor sem esquema e o expanda para GitHub — por exemplo: se `"://" not in url` e `url` não começa com `/` e corresponde a `^[A-Za-z0-9._~-]+(/[A-Za-z0-9._~-]+){1,2}$`, então `url = "https://github.com/" + url`. É uma mudança de ~3 linhas, sem alterar ordem, conteúdo ou colunas da tabela gerada, e sem tocar em pacotes com escopo (`@scope/name`, que já caem no fallback npmjs). Alternativas **não** recomendadas: editar o Markdown gerado à mão (seria sobrescrito na próxima geração) ou remover os links (perde informação de proveniência).

**Como testar a correção:** (1) teste unitário novo `tests/test_third_party_notices.py` em `unittest` (padrão dos testes Python existentes, executável por `python -m unittest discover -s tests`), chamando `repository_url()` com manifests representativos — `"repository": "owner/repo"`, `{"url": "git+https://github.com/owner/repo.git"}`, `"github:owner/repo"`, `"git://github.com/owner/repo"`, campo ausente, `@scope/name` — e afirmando que **todo resultado começa com `https://`**; (2) regenerar o arquivo com `node_modules` instalado e conferir que o diff se limita aos alvos de link (sem reordenação nem mudança de colunas); (3) rodar o verificador de links Markdown sobre `THIRD_PARTY_NOTICES.md` e exigir **0 links relativos não resolvidos**; (4) confirmar que `python -m unittest discover -s tests` continua com o mesmo número de falhas pré-existentes (hoje 1, `test_installed_npm_tree_matches_lockfile`, por ausência de árvore npm instalada). **Nesta tarefa o gerador não foi alterado** — apenas o achado, a causa e a recomendação foram documentados, conforme o escopo autorizado.
